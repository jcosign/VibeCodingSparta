# INTEGRATION - D1~D4 교안 ↔ 프로젝트 코드 연결표 + 실측 비교 + 트러블슈팅

이 문서는 13주차 교안(D1~D4)에서 배운 내용이 `app.py`·`rag.py`·`embed.py`·`docs.py`의 어디에 들어 있는지,
그리고 임베딩 모델을 바꾸면 검색 품질이 실제로 어떻게 달라지는지(직접 측정한 값)를 정리합니다.

## 1. 교안 ↔ 코드 연결표

| 교안 | 교안에서 배운 것 | 프로젝트 코드 | 교안과 같은 점 / 다른 점 |
|---|---|---|---|
| D1 2-2·3-1 | RAG = 검색 → 근거로 답 + 출처 | `rag.py` `MiniRAG.answer()` | 반환값 `(답변, hits)` 동일. 답변 형식 `[제목] 본문 (출처: …)` 동일 |
| D1 3-5, D4 3-4 | 근거 없으면 "관련 문서를 찾지 못했어요." | `answer()`의 `min_score` 검사 | 교안 코드는 `if not hits`만 검사(그런데 `search`는 항상 k개를 돌려줘서 이 분기에 거의 안 들어감). D4 부록 FAQ의 "임계값"을 추가함 → §4 참고 |
| D2 2-2 | `embed(text)` → 고정 길이 벡터, 정규화 | `embed.py` `embed()` | 교안: 문자 n-그램 해싱 512칸. 프로젝트: `intfloat/multilingual-e5-small` 384칸, `normalize_embeddings=True`로 L2 정규화 |
| D2 3-2 | `cosine(a, b)` = 정규화된 벡터의 내적 | `embed.py` `cosine()` | 교안 코드 그대로 |
| D2 3-3 | `max(cands, key=lambda c: cosine(q, embed(c)))` | `examples/example_01_embed_similarity.py` | 교안 코드 그대로 |
| D2 4-2 | 실무에선 `embed()` 안만 갈아끼운다 | `embed.py` 전체 | 함수 이름·반환 형식을 유지해서 `rag.py`는 거의 그대로 |
| D3 2-2 | `chromadb.Client()` + `create_collection("rag_"+uuid, metadata={"hnsw:space": "cosine"})` | `MiniRAG.__init__()` | 교안 코드 그대로 |
| D3 2-3 | `add(ids, documents, embeddings, metadatas)` - 임베딩을 직접 넣음 | `MiniRAG.add()` | 교안 코드 그대로 + 문서는 `prefix="passage: "`로 임베딩(§3) |
| D3 2-4 | `build()`로 전체 색인, 개수 반환 | `MiniRAG.build()` | 교안 코드 그대로 |
| D3 3-2·3-3 | `query(query_embeddings=[qv], n_results=k)`, 유사도 = `1 - 거리` | `MiniRAG.search()` | 교안 코드 그대로. 실측: Chroma 결과와 폴백(순수 파이썬 내적) 점수가 소수 넷째 자리까지 같음(예: 반품정책 0.8657) |
| D3 3-6 | Chroma 없으면 순수 파이썬 폴백 | `search()` 마지막 두 줄 | 교안 코드 그대로 |
| D3 4-3 | 정답 표로 검색 정확도를 숫자로 | `examples/example_02_rag_search.py` | 교안 코드 형태 그대로, 질문을 6개로 늘림 |
| D4 1-3 | `chunk(text, size=40)` | `docs.py` `chunk()` | 교안 코드 그대로(겹침 없음). 8개 FAQ는 짧아서 프로젝트는 "항목 1개 = 청크 1개"로 색인(D4 2-1) |
| D4 4-2 | 검증 3문 ③ "출처 원문과 답이 일치하나?" | `cli_augment.unverified_numbers()` + `app.py` | CLI가 다듬은 답에 근거 문서에 없는 숫자가 있으면 경고 |
| D4 4-3 | 지식베이스에 넣기 전 민감정보 점검 | `cli_augment.py` 주석, `docs.py`는 가짜 샘플 | CLI에는 검색된 근거 k개와 질문만 보냄 |
| 프로젝트 PDF | 하이브리드 CLI(`USE_CLAUDE_CLI`/`USE_CODEX_CLI`), 없으면 조용히 skip | `cli_augment.py`, `app.py` 하단 | 박스 제목 "🤖 Claude CLI가 다듬은 답변" |

## 2. 실측 비교 - 임베딩 방식별 검색 품질

측정 스크립트: 과제 폴더 밖 `검증/compare_embeddings.py` (같은 `docs.py` 8개 문서, 질문 12개)
측정일·환경: 2026-10-27, Windows 11, Python 3.12.10, sentence-transformers 6.2.0, torch 2.14.1(CPU)

| 방식 | top-1 정확도 | 비고 |
|---|---|---|
| A. 해시(D2 교안 방식, 문자 1·2-그램 512칸) | **8/12** | 글자가 겹치면 잘 맞힘. "돈을 다시 돌려받고 싶어요" → 환불처리 8위(꼴찌) |
| B. `sentence-transformers/all-MiniLM-L6-v2` | **4/12** | "배송 얼마나 걸려요?" → 배송기간 **8위(꼴찌)**, "언제 도착해요?"·"주말에도 배송되나요?"도 배송기간 8위 |
| C. `intfloat/multilingual-e5-small`, 질문 `query: ` / 문서 `passage: ` (**현재 embed.py·rag.py 방식**) | **11/12** | 틀린 1개: "사이즈가 안 맞아서 다른 걸로 바꾸고 싶어요" → 포인트적립 1위, 교환방법 2위 |
| D. `multilingual-e5-small`, 질문·문서 모두 `query: ` | 10/12 | C보다 1개 더 틀림("물건 돌려보내고 싶어요" → 반품정책 4위) → C 방식을 채택 |

질문별 결과(정답 문서의 순위, 8개 중):

| 질문 | 정답 | A 해시 | B MiniLM | C e5 |
|---|---|---|---|---|
| 반품하고 싶어요 | 반품정책 | 1 | 3 | 1 |
| 배송 얼마나 걸려요? | 배송기간 | 1 | 8 | 1 |
| 포인트 어떻게 쌓나요 | 포인트적립 | 1 | 1 | 1 |
| 돈을 다시 돌려받고 싶어요 | 환불처리 | 8 | 6 | 1 |
| 물건 돌려보내고 싶어요 | 반품정책 | 7 | 2 | 1 |
| 언제 도착해요? | 배송기간 | 4 | 8 | 1 |
| 환불 언제 돼요? | 환불처리 | 1 | 1 | 1 |
| 쿠폰 두 장 같이 써도 돼요? | 쿠폰사용 | 1 | 1 | 1 |
| VIP 되려면요? | 회원등급 | 1 | 1 | 1 |
| 주말에도 배송되나요? | 배송기간 | 1 | 8 | 1 |
| 사이즈가 안 맞아서 다른 걸로 바꾸고 싶어요 | 교환방법 | 4 | 6 | 2 |
| 상담원이랑 통화하고 싶어요 | 고객센터 | 1 | 6 | 1 |

`python3 rag.py` 실측 출력(Chroma 사용, k=2):

```
색인 문서 수: 8 | Chroma: True
Q: 반품하고 싶어요            근거: [('반품정책', 0.8657), ('환불처리', 0.8485)]
Q: 배송 얼마나 걸려요?        근거: [('배송기간', 0.8748), ('고객센터', 0.8218)]
Q: 포인트 어떻게 쌓나요        근거: [('포인트적립', 0.8317), ('고객센터', 0.8144)]
Q: 돈을 다시 돌려받고 싶어요   근거: [('환불처리', 0.8235), ('고객센터', 0.8231)]
```

### 읽을 때 주의할 점 (실측에서 드러난 한계)

1. **e5의 점수는 0.78~0.91 사이에 몰려 있습니다.** 교안 예시(0.71, 0.42처럼 넓게 퍼진 점수)와 모양이 다릅니다. 순위(몇 등인가)는 잘 맞지만 점수 절댓값으로 "관련 있다/없다"를 가르기는 어렵습니다(§4).
2. **"돈을 다시 돌려받고 싶어요"는 1위가 아슬아슬합니다.** 환불처리 0.8235 vs 고객센터 0.8231(차이 0.0004). 맞히긴 했지만 문서를 조금만 바꿔도 뒤집힐 수 있습니다.
3. **"느려요 vs 빨라요"는 e5도 구별하지 못했습니다.** `examples/example_01_embed_similarity.py` 실측: "배송이 너무 느려요" 대비 `배송이 빨라요 0.931 > 배송 지연 불만 0.909 > 가격이 저렴해요 0.874`. (`embed.py`의 데모 문장 "배송이 빨라 좋아요"는 0.909로 "배송 지연 불만"과 같은 점수.) D2 3-4의 "실무 의미 임베딩이라면 반대 뜻이라 낮게 나온다"는 이 작은 모델에서는 성립하지 않았습니다. 작은 임베딩 모델은 '배송'이라는 주제는 잘 잡지만 반대 뜻 구별은 약할 수 있습니다.
4. 질문 12개·문서 8개짜리 작은 시험입니다. "e5가 항상 낫다"는 일반 결론이 아니라 **이 FAQ에서는** 이렇게 나왔다는 기록입니다.

## 3. 왜 `query: ` / `passage: ` 접두어를 붙이나

`multilingual-e5` 계열은 학습할 때 질문 앞에 `query: `, 문서 앞에 `passage: `를 붙여서 학습한 모델입니다(모델 카드 안내). 그래서 `embed(text, prefix="query: ")`를 기본으로 두고, `rag.py`의 `add()`만 `prefix="passage: "`로 색인합니다. 모델(자)은 같으므로 D3 3-1의 "같은 자로 재야 비교가 된다"는 원칙은 그대로입니다. 위 표 C vs D처럼 이 FAQ에서는 접두어를 구분한 쪽이 11/12 vs 10/12로 조금 나았습니다.

## 4. 임계값(`MIN_SCORE = 0.80`) 실측

같은 스크립트로 "지식베이스에 답이 없는 질문" 5개의 1위 점수도 쟀습니다(방식 C).

| 답이 없는 질문 | 1위 문서(점수) |
|---|---|
| 해외 배송도 되나요? | 배송기간 (0.8612) |
| 우리 회사 주가 얼마예요? | 고객센터 (0.7803) |
| 이 상품 언제 재입고돼요? | 반품정책 (0.8654) |
| 오늘 날씨 어때? | 배송기간 (0.8186) |
| 환불 수수료 얼마예요? | 환불처리 (0.8654) |

- 정답이 있는 질문 12개의 1위 점수: **0.8091 ~ 0.8991**
- 답이 없는 질문 5개의 1위 점수: **0.7803 ~ 0.8654**
- **두 범위가 겹칩니다.** 그래서 어떤 임계값을 골라도 둘을 깔끔히 나눌 수 없습니다.
- `0.80`은 "정답 질문은 하나도 막지 않는 가장 높은 값 근처"로 고른 값입니다. 이 값으로는 답 없는 질문 5개 중 **1개("우리 회사 주가")만** "관련 문서를 찾지 못했어요"로 처리되고, 나머지 4개는 가장 가까운 문서를 그대로 보여 줍니다.
- 예: "해외 배송도 되나요?" → `[배송기간] 일반 배송은 2~3일…`을 답으로 보여 줍니다. 문서 원문을 그대로 보여 줄 뿐 '해외 배송 가능'을 지어내지는 않지만, D4 3-4가 기대한 "못 찾았다"는 나오지 않습니다. **그래서 근거 표의 출처·점수를 사람이 확인하는 단계(D4 4-2)가 여전히 필요합니다.**
- 앱 사이드바의 "최소 유사도" 슬라이더로 값을 바꿔 보며 이 트레이드오프를 직접 확인할 수 있습니다(0.87로 올리면 답 없는 질문 5개는 모두 걸러지지만 정답 질문도 12개 중 10개가 "못 찾았다"가 됩니다 - 위 측정값으로 계산한 결과).
